# Architecture Decision Records

Eight short records, defended in the Top-8 viva. Status of all: **Accepted (2026-10-17)**.

## ADR-1: Node 20 + Express 5 + `pg`, plain JavaScript
**Context:** 4h15m sprint; the grader compares JSON literally; `node:20-alpine` is the pre-pulled runtime.
**Decision:** Express 5 (async errors reach one error handler), raw SQL through `pg`, no TypeScript build step.
**Consequences:** One error handler produces every `{"error":{code,message,details}}` body. Tests run with `node --test` and need no loader. Types aren't enforced, so request validation is explicit (`lib/validate.js`).

## ADR-2: Hybrid relational + JSONB schema
**Context:** Sports must be pure data, and a mystery sport arrives as JSON at grading time.
**Decision:** Identifiers and relations are real columns with keys (sports, leagues, matches, events, squads, players, variants, orders). Sport configs, event payloads and stored idempotent responses are JSONB.
**Consequences:** A new sport needs no migration or code. Domain code branches only on `scoring_model`, never on sport or event names.

## ADR-3: Append-only event log with a per-match row lock
**Context:** Scores must be rebuilt from the log; corrections use compensating events.
**Decision:** `events` rows are never updated. Every read projects the score from the log (`scoring/engine.js#project`). An append takes `SELECT … FOR UPDATE` on the match row, so sequence numbers are gap-free under concurrency. `event_id` is unique; the stored response is replayed for an identical body.
**Consequences:** Standings recompute from scratch on every call (edge case 5 works for free). Reads cost O(events), which is fine at league scale.

## ADR-4: Conditional decrement for stock (NFR-3)
**Context:** 20 simultaneous buyers for 1 unit.
**Decision:** `UPDATE variants SET stock = stock - q, reserved = reserved + q WHERE variant_id = $1 AND stock >= q`, for all items (sorted to avoid deadlocks) in one transaction. Payment failure releases the reservation; success moves reserved → sold. `CHECK (stock >= 0)` backs it up.
**Consequences:** No read-then-write race and no overselling. The order id is claimed first, so concurrent identical retries replay instead of double-charging.

## ADR-5: RBAC as policy-as-code with HS256 JWTs
**Context:** 5 roles, strict tenant isolation, and authorization must be checked before anything else.
**Decision:** `rbac/policy.js` maps action → role → predicate(principal, target). The default is deny, and every non-super-admin predicate requires the same tenant. JWTs are hand-verified: only `alg: HS256`, constant-time signature compare, mandatory `exp`. Probe routes are mounted before the body parser.
**Consequences:** Every cell of the spec matrix is a unit test. Cross-tenant access is always 403, never 404.

## ADR-6: Pure domain core, thin persistence services
**Context:** A coverage bonus is voided if a declared figure is more than 2 points above the measured one; judges may run tests without a database.
**Decision:** All rules (fixtures, scoring, standings, roster checks, pricing, sync mapping) are pure functions. `service.js` files only load and save.
**Consequences:** `./run_tests.sh` measures real coverage with no DB, and `COVERAGE.json` is generated by `scripts/coverage-areas.mjs`. Live DB behaviour is covered by `scripts/e2e.sh`.

## ADR-7: MinIO opt-in, receipts in Postgres
**Context:** Docker Hub refuses pulls of `minio/minio:RELEASE.2024-09-22T00-33-43Z` (checked 2026-10-17), and one unpullable image fails the whole `compose up` (−10).
**Decision:** The `storage` service stays in compose at the exact bundle tag under profile `objectstore`. Receipt PDFs are stored in `orders.receipt_pdf` (bytea) and returned base64 in the checkout response.
**Consequences:** The default `docker compose up -d --build` never depends on MinIO. Start it with `docker compose --profile objectstore up -d` where the image is available.

## ADR-8: Offline-first Expo app over a shared sync service
**Context:** NFR-4 desk check (airplane mode, force-close, sync) plus the `/offline-sync` script.
**Decision:** The app (React Native + Expo, expo-sqlite + Drizzle) caches reads in SQLite and queues actions in the exact spec 16 format. It syncs through `/api/v1/offline-sync`, which calls the same `sync/service.js#offlineSync` as `/audit/v1/offline-sync`. The token lives in `expo-secure-store` (Android Keystore).
**Consequences:** One conflict-resolution implementation is graded by the script and also used by the app, and queued actions survive restarts.
